# Reader guide: reproducibility and scope

Use the repository at a fixed commit and follow the README Quickstart. The
runnable examples create only synthetic inputs under `tutorial/demo/`.

```bash
python -m pip install -e '.[dev]'
python -m pytest tests -q
python tutorial/make_demo.py
medaudit audit --config tutorial/demo/audit.json --out tutorial/demo/report.txt
medaudit audit --config tutorial/demo/leaked.json --out tutorial/demo/leaked-report.txt
python tutorial/worked_examples.py
```

`make_demo.py` generates A–D. The two CLI runs exercise a generated split and a
split with a deliberately planted group overlap. A leakage verdict is report
content; the CLI exits successfully after writing either report. The worked
examples are fixed arithmetic inputs for existing metrics.

For your own audit, supply a row-aligned manifest CSV and `features.npy` through
a JSON config. Include the split assignment of record and usable repeated group
IDs to assess group overlap in that assignment. Without them, the generated split
cannot provide assurance about patient separation in an earlier training/test
split. Cosine-similarity results are candidate pairs for inspection, not identity
findings.

The automated command runs an attribute probe and a leakage screen. Calibration,
prevalence, external evaluation, feature extraction, and HTML reporting are not
automated modules in v0.2.0. See [DESIGN.md](../DESIGN.md) for the current module
scope and [RUNNING.md](../tutorial/RUNNING.md) for expected outputs and input
conventions.

The tutorial's historical cystoscopy values are aggregate, single-seed teaching
examples. They are not regenerated by this repository and are not clinical
validation. No patient data, images, features, or model weights are required for
the synthetic tutorial.
